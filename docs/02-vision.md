# 02 · 願景：Agent Native 的「睿鏡 PeakLens」

## 一句話

**睿鏡 PeakLens**：台灣不動產的即時上帝視角。你對城市說話，地圖就回答——而且每一個答案都能回溯到一個 FUNRAISE MCP 工具呼叫與它的資料期間。

（代號。備選：「方睿天眼」、PeakEye、OverPeak。Peak 家族命名與 PickPeak／BizPeak 一致；「鏡」對應核心機制「視角＝鏡頭（Lens）」。）

## 為什麼是「Agent Native」而不是「有 AI 功能的地圖」

| 傳統 GIS／地產平台 | Agent Native 睿鏡 |
|---|---|
| 人操作介面 → 介面查資料庫 | **人對 agent 說話 → agent 呼叫工具 → 地圖是 agent 的渲染目標** |
| 圖層是產品經理預先定義的 | 圖層是工具呼叫的結果，可即時組合（「把都更疊在資本流上」） |
| 答案是一個數字或一張表 | 答案是**鏡頭移動＋圖形＋一段可回查的敘事** |
| 每個客群一個產品 | 同一張地圖，換一個「鏡」（Lens）就是另一個產品 |
| 資料新不新，用戶不知道 | 每個圖層帶資料時間戳與來源，「新鮮度」是產品功能 |
| 結束於「看見」 | 結束於「行動」：DD memo、選址提案、搬遷計畫、遷入企業名單推給生態系 |

這正是 6 月策略會議的核心命題落地：「把資料、模型與專業經驗轉化為可執行、可驗證、可複製的工作流」——只是這次工作流長在地圖上，用聲音驅動。

## 三個設計原則

1. **Present × Past × Future 三軸同框**
   GEV 只有現在。睿鏡把實價登錄（2012–）與建照／未來開發（→2030）放進同一個時間軸；拖一下就能看城市如何被買賣、被更新、被建造。「時光模式」是我們最不容易被複製的體驗。
2. **Lens 即產品**
   投資人鏡、開發商鏡、企業選址鏡、城市治理鏡、學研鏡。同一底座，不同圖層預設、KPI、建議指令、輸出物與價格。新客群＝新鏡，不是新產品線。
3. **可回查的敘事（Provenance HUD）**
   每句回答下方顯示工具呼叫卡（工具名、參數、筆數、延遲、資料期間）。這是 FUNRAISE MCP「每筆結論皆附資料來源與期間」原則的視覺化，也是對「資料新鮮度尚未標準化」這個已知落差最誠實的回應：看得見的時間戳比口頭承諾更可信。

## 核心體驗（承襲 GEV，換成台灣土地經濟）

| GEV 元素 | 睿鏡對應 |
|---|---|
| 即時飛機／船／衛星 | 即時登錄的成交脈衝、上市櫃資產交易、公司登記遷徙弧線、TDX 公車／捷運／YouBike、CCTV |
| Cockpit（第一人稱） | **現勘鏡**：街景視角＋手機 AR，指著大樓就出謄本／分區／歷史成交 |
| Orbital View | **環繞鏡**：鎖定一棟大樓 360° 環繞，逐層租戶與銷控 |
| Detection Overlay | **供給雷達**：建照／未來開發以幽靈建物＋完工年浮標標示 |
| Sensor styles | 夜視／熱感（單價熱度）／藍圖（分區） |
| 五字 AI HUD | 「信義區 · 商辦 20 · 都更 3 · 2028 供給」即時讀出 |
| Scene director | **導覽腳本**：RAISE DAY、接待中心、首長簡報用的 90 秒電影式巡航 |
| 28 個語音工具 | GEV 相機／標註工具 ＋ FUNRAISE MCP 30+ 工具 ＋ Lens 工具（切鏡、時間軸、輸出） |

## 成功的樣子（24 個月）

- 「看台灣不動產」的預設畫面：媒體引用、首長辦公室與建商接待中心的牆上是睿鏡。
- 每個鏡至少一個付費標竿客戶：壽險／REITs、建商、企業總務、市府、大學。
- FUNRAISE MCP 月工具呼叫量成為公司北極星，睿鏡是最大的呼叫來源與最好的銷售員。
- 生態系夥伴把自有資料封裝成 MCP 工具、在睿鏡上以圖層販售（Lens Marketplace）。
